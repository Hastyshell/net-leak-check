# Symptom → cause → evidence → fix

Collected from real-world macOS diagnoses (Clash Verge Rev 2.5.x, mihomo 1.19.x; setups with a company VPN
such as CorpLink/飞连, and VPS nodes whose TCP egress differs from their UDP egress, e.g. via WARP).
Use the evidence column to confirm before fixing.

| # | Symptom | Root cause | Evidence that confirms it | Fix (see fix-templates.md) |

| 1 | WebRTC / STUN shows the real home IP while TUN is on | Proxy nodes have no `udp` (vmess/trojan default `udp: false`). mihomo skips adapters without UDP while matching rules and finally falls through to **DIRECT** | `udp_check.sh`: mapped = HOME; Clash UDP connections with empty `rule` and chain `DIRECT`; `/proxies` shows `udp:false` | `udp: true` on every node (profile script or edit profile) |

## Useful facts

- `scutil --dns`: a supplemental resolver with an empty match domain acts as the default resolver; the
  lowest `order` wins. `SupplementalMatchDomainsNoSearch = 1` stops match domains being added to the search list.
- mihomo only enables TUN IPv6 (`inet6-address`) when the machine has a global IPv6 address.
- mihomo DNS upstream `127.0.0.1` works in TUN mode (loopback is not bound to the NIC); a corporate DNS
  IP that is only reachable through another utun does not (DIRECT/DNS dials are bound to the default NIC).
- Verge (macOS, TUN on) sets the primary service DNS to the placeholder 114.114.114.114 and backs up the
  original under `.original_dns/<service-id>`.
- CorpLink logs (readable): `/usr/local/corplink/logs/corplink.log` — `Client Config result` holds
  split domains/routes; `DisconnectVpn` with a gRPC client = disconnected from its own UI.
